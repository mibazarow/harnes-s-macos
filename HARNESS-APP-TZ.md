### 0.2 Обязательное использование GSD Core

**GSD Core обязателен для исполнения.** Не «по желанию» — часть процесса, наравне с тестами и коммитами.

Почему: объём (40–60k строк Swift, 9 этапов) не помещается в одну сессию. Без GSD теряется состояние, планы разваливаются, параллельные исполнители конфликтуют.

Порядок запуска:
1. `npx @opengsd/gsd-core@latest --kilo --global` (уже установлен, 1.18.0).
2. В каталоге проекта — `/gsd-new-project`.
3. Загрузить в него **этот файл** (`HARNESS-APP-TZ.md`).
4. GSD строит `.planning/PROJECT.md`, `REQUIREMENTS.md`, `ROADMAP.md`, `STATE.md`, где этапы P0–P9 из §26 становятся фазами.
5. Соответствие фиксируется: **одна фаза GSD = один этап Pn**. Не дробить иначе.

Цикл на фазу: `/gsd-discuss-phase N` → `/gsd-plan-phase N` → `/gsd-execute-phase N` → `/gsd-verify-work N` → `/gsd-ship N`.

Правила:
- Фаза не начинается без плана.
- Одна задача плана = один концерн.
- Параллельные исполнители — в отдельных worktree.
- Гейт перед мержем: сборка + тесты + критерии приёмки фазы. Красный гейт — не мержим.
- `STATE.md` обновляется после каждой фазы; пауза — `/gsd-pause-work`.

Если GSD недоступен — восстановить (`/gsd-help`, `/gsd-health`); работать вручную с файлом прогресса — деградация, а не норма.

### 0.3 Жёсткие правила

- **Не менять стек.** Swift 6 + SwiftUI/AppKit + GRDB + SQLite. Никакого Tauri, Node, Rust, WebView, React, Electron.
- **Только один чат.** Никаких списков сессий, заметок, канбана и боковых панелей. Всё управление — через чат и меню шапки.
- **Не менять имена инструментов агента** (§9) — на них завязаны промпты и скиллы.
- **Данные не удаляются из БД.** Компакция и «очистить вид» — только отображение.
- **Секреты хранятся только в локальной БД** `~/HARNES_S_DATA/database/harness.db`. Keychain не используется — осознанное решение для личного устройства.
- **Базовый дизайн — HIG и системные контролы; терминальный вид транскрипта — утверждённое пользователем исключение** (§17).
- **Каждый срез — рабочий и закоммиченный.** Не оставлять недоделанное.

### 0.4 Если в ТЗ чего-то нет

1. Смотри оригинал Project-S как **эталон поведения инструментов**: `PROJECT-S/src-tauri/src/agent/**`, `llm/**`, `mcp/**`, `scheduler/**`. Код не копировать, поведение — сохранять.
2. Если и там нет — выбрать минимальное решение, не расширяющее scope, и записать в §28.
3. Не задавать вопросы по мелочам, решаемым по HIG или по оригиналу.

### 0.5 Definition of Done для среза

- Сборка без предупреждений (для новых файлов — warnings as errors).
- Тесты: новые есть, старые зелёные.
- Ручная проверка сценария из §26.
- Коммит с осмысленным сообщением.

### 0.6 Чего нельзя делать «для скорости»

- Отключать strict concurrency.
- Держать историю в памяти UI целиком.
- Делать `NSTextView` на весь транскрипт.
- `try!`/`fatalError` в путях работы с пользовательскими данными.
- Класть ключи в JSON/логи/UserDefaults.
- Игнорировать `.gitignore` при индексации.
- Блокировать main actor диском/сетью.

## 1. Задача

Сделать **нативное macOS-приложение** — **персональный ассистент и рабочий харнес в одном лице**, с которым пользователь общается как с коллегой: один непрерывный чат, одна личность, одна память.

Это помесь двух ролей:

1. **Персональный ассистент** (в духе OpenClaw): помнит пользователя, его предпочтения и договорённости, ставит напоминания, ведёт расписания, ищет в интернете, разбирает документы, сообщает о событиях, доступен из меню-бара и по горячей клавише.
2. **Харнес-разработчик**: работает с проектами — папками с кодом, открывает файлы, ищет по кодовой базе, правит диффами, запускает терминал, git, тесты, браузер, SSH, MCP и скиллы.

Обе роли живут **в одном чате и в одной непрерывной истории**. Нет переключателя «режим ассистента / режим кодера». Пользователь просто пишет: «напомни в 18:00», «что мы решали по авторизации», «почини сборку в проекте X» — и агент сам понимает, что делать.

**Это не порт Project-S.** Project-S остаётся как есть и не трогается. Из него берём поведение агентного ядра и инструментов — как эталон, не как источник данных, экранов или дизайна.

Ключевые свойства:
1. **Один чат навсегда.** Никаких сессий, вкладок, списков чатов. Открыл — и продолжаешь разговор с тем же собеседником.
2. **Проекты — это папки, а не CRM.** Агент знает несколько рабочих папок, помнит контекст каждой, переключается по команде. Никакого канбана, статусов и дедлайнов.
3. **Одна личность и одна память.** Профиль пользователя, предпочтения, решения — общие для всех проектов; плюс память, привязанная к конкретной папке.
4. **Нативный macOS**: HIG, системные контролы, SF Symbols, темы, доступность. Не веб-интерфейс в окне.
5. **Быстрый на длинной истории**: виртуализованный транскрипт, живое окно, компакция без потери данных.
6. **Локальность**: данные, индексы, ключи — на машине. Никакого облака и телеметрии.

### 1.1 Что НЕ входит (явно)

- **CRM и управление проектами как сущностью**: канбан, статусы, дедлайны, таймеры, чек-листы задач, «Мои задачи».
- **База знаний / заметки**: vault, дерево папок, Markdown-редактор заметок, версии заметок, чат заметок.
- **Многочатовость**: список сессий, создание/архив/удаление чатов, TTL.
- Кроссплатформа, Intel, Windows, Linux, iOS.
- Миграция данных из Project-S.
- Синхронизация между машинами, аккаунты, облачный сервер.
- Плагины на JS.

При этом **работа с проектами-папками входит**: агент открывает, читает, индексирует, правит и запускает код в выбранной папке, помнит контекст по каждой папке и умеет переключаться между ними. Просто это не отдельный экран «Проекты», а свойство разговора.

### 1.2 Критерий «готово»

На чистом Mac: онбординг → провайдер → чат. Агент:
- помнит, кто пользователь и о чём договорились;
- ставит напоминания и выполняет расписания;
- открывает любую рабочую папку, читает и правит код, запускает команды и тесты;
- переключается между папками внутри одного разговора;
- подключает MCP и скиллы;
- через 500 ходов не тормозит и не раздувает окно.

## 6. Единственный чат

### 6.1 Модель

- В БД ровно один чат (`chats.kind = 'harness'`), гарантируется уникальным индексом.
- `harness_state` хранит `chat_id` и `working_dir`.
- Нет UI для создания, переименования, удаления, архивации чата.

### 6.2 Скрытые потоки

Фоновые запуски (расписания, субагенты, длинные серии инструментов) не должны превращать основной чат в свалку:

- Они пишутся в `threads` (под-транскрипт) и в `messages.thread_id`.
- В основном чате появляется **карточка**: `▶ Расписание «Проверка сайта» · 13:00 · выполнено · 2 мин` + «Показать ход».
- Разворот подгружает поток лениво и виртуализованно.
- Карточка остаётся в истории навсегда.

### 6.3 Компакция

**Смена провайдера на меньшее окно (реализовано).** История в БД не зависит от окна. При отправке `ContextComposer` строит план: system + саммари + хвост в пределах `contextWindow × threshold`; всё, что не влезло, уходит в чекпоинт-саммари, а не удаляется. Если после смены провайдера текущая история больше нового порога, в чат добавляется системное уведомление с числами; фактическое сжатие происходит на следующем ответе. Футер показывает `использовано / окно` и предупреждает цветом при превышении. Тесты: `Tests/ContextComposerTests.swift` (400 сообщений → окно 250k, 900k-сообщения → окно 8k).

- Чекпоинты-саммари, порог от окна модели (`compactionThresholdPercent`, по умолчанию 80%).
- Порог считается по уже сжатому вью (system + чекпоинты + хвост), а не по сырому транскрипту.
- После компакции вью схлопывает покрытые сообщения в узел «Сжато N сообщений»; данные остаются.
- Триггеры: 60–70% окна, граница задачи, `/compact`, перед «очистить вид».

### 6.4 «Очистить вид»

Кнопка/⌘⇧K:
- ставит маркер-эпоху;
- всё выше маркера сворачивается в один узел;
- модель получает свежее окно (system + саммари + хвост);
- поиск и память по всей истории работают.

Не удаляет ничего. Не создаёт вторую сущность.

### 6.5 Проекты-папки (workspaces)

Проект здесь — это **папка с файлами**, а не сущность с канбаном и статусами. Но агент помнит проекты и умеет между ними переключаться.

Модель:
- `workspaces` — список известных папок: `root` (уникальный путь), `name`, `pinned`, `last_opened_at`, `notes` (короткая заметка агента «что это за проект»), `git_remote`, `default_branch`.
- `harness_state.active_root` — одна активная папка в текущий момент. В один момент времени агент работает только в одной.
- Память делится на **глобальную** (о пользователе и его предпочтениях) и **привязанную к папке** (`memory.workspace_root`).
- У каждой папки может быть свой `AGENTS.md` — проектные правила; он попадает в контекст только когда папка активна.

Переключение:
- Чип в шапке: `📁 project-x ▾` → меню: список папок, «Открыть другую папку…», «Показать в Finder», «Забыть папку».
- `/focus <имя>` — переключиться командой.
- Агент сам может предложить переключиться, но **не переключает молча**: действие требует подтверждения (смена папки меняет область записи).
- При переключении: сохранить позицию скролла для папки, подгрузить её `AGENTS.md` и память, запустить/продолжить индексацию, обновить `harness_state.active_root`.
- Если папка не существует (удалили/переместили) — предложить найти её или забыть.

Область записи:
- Относительные пути инструментов — от активной папки.
- Выход за неё — только с подтверждением (кроме явно разрешённых папок).
- Можно открыть папку **только на чтение** (флаг `read_only`) — удобно для чужих репозиториев.

Отличие от CRM:
- Нет статусов, дедлайнов, участников, бюджета.
- Нет отдельного экрана «Проекты» и инспектора: список папок — меню чипа в шапке.
- Нет ручного создания «проекта»: её создаёт выбор папки.

### 6.6 Контекст проекта в разговоре

Когда активна папка, в системный промпт добавляется компактный **project pack**:
- имя и путь папки, git-ветка, грязный/чистый worktree;
- `AGENTS.md` (если есть);
- структура верхнего уровня (2–3 уровня, без мусора);
- список ключевых файлов по расширениям;
- записка агента «что это за проект» (`workspaces.notes`), если он её составил;
- память, привязанная к папке (top-k).

Когда папка не выбрана (режим ассистента) — project pack отсутствует, работают только глобальная память, расписания и бытовые инструменты.

Один и тот же чат может содержать: «напомни…» → «переключись на X» → «почини…». Это нормальный сценарий, не требующий отдельного режима.

## 7. Агентское ядро

### 7.1 Луп

`AgentLoop` (actor):
1. `ContextComposer` собирает окно.
2. Провайдер отвечает стримом.
3. Есть tool-calls → выполнить (параллельно, где безопасно) → добавить результаты → повторить.
4. Нет — финализировать, записать сообщение, обновить usage.

Инварианты:
- Отмена мгновенная, с закрытием соединения и сохранением частичного текста.
- Ошибка инструмента не роняет сессию.
- Каждый шаг — в append-only лог.
- Tool output > 20 KB → артефакт.

### 7.2 Контекст

Бюджет **20–30k токенов** (настраивается):

| Компонент | Бюджет |
|---|---|
| System prompt | 2–4k |
| Рабочая папка: структура + `AGENTS.md` | 2–5k |
| Рабочее саммари | 3–6k |
| Последние реплики | 6–10 реплик |
| Top-k памяти и результатов поиска | 1–3k |
| Резерв под ответ | 2–4k |

System prompt — единый для обеих ролей:
- **Личность**: «Харнес» — личный ассистент и инженер пользователя. Обращение на «ты», коротко, по делу, без воды и без лести. Может пошутить, но не сюсюкает.
- **Две роли без переключателя**: бытовые задачи (напомни, найди, посчитай, разбери документ) и разработка (код, git, тесты, терминал). Агент сам определяет, что нужно, по запросу.
- **Правила инструментов**: сначала поиск/чтение, потом правка; диффы; не переписывать файл целиком; не выдумывать содержимое файлов.
- **Границы**: активная папка и запрет выхода без подтверждения; необратимые действия — подтверждать.
- **Инициатива**: если задача размыта — задать один уточняющий вопрос, а не гадать. Если можно сделать сразу — сделать.
- **Память**: использовать `user`-память всегда; `workspace`-память — когда папка активна; не выдумывать факты о пользователе.
- **Инструменты**: список активных (ленивое раскрытие схем).
- **Стиль**: `style_profile` пользователя, если есть.

### 7.3 Разрешения и path-policy

- Область по умолчанию: рабочая папка. Запись вне — подтверждение.
- Опасное: удаление, shell, сеть, SSH, установка пакетов, запись в системные каталоги.
- `ConfirmBroker`: async-запрос в UI; варианты «Разрешить», «Разрешить на сессию», «Отклонить».
- Автопилот: снимает подтверждения, **кроме** path-policy и необратимых операций.
- Все удаления — в `trash/`, с `undo_last`.
- `CommandGuard`: блокирует очевидно разрушительные команды (`rm -rf /`, `dd of=/dev/disk*`, `chmod -R 777 /`) даже в автопилоте.

### 7.4 Inline tool-calls

Если провайдер не прислал нативных `tool_calls`, распознать текстовые диалекты:
`<tool_call>…`, `<|tool_call|>`, `<function_calls><invoke>`, `<function=…>`, ```json-блок.
Вырезать разметку из `content`/`reasoning`, превратить в настоящий вызов. JSON-формы — только если имя есть в каталоге.
Вызов неизвестного (deferred) инструмента автоматически включает его через `enable_tools`.

### 7.5 Артефакты и вложения

- Вложения пользователя: изображения/файлы, копия в `attachments/`, превью в сообщении.
- Крупные результаты — `artifacts/` (контент-адресация), в контекст ссылка + превью.
- Vision: если модель поддерживает изображения — отправлять; иначе OCR/описание локально.

### 7.6 Проверки перед записью

- Перед изменением файла — снапшот в `versions/` (без git).
- Все правки агента собираются в список диффов; режим «Принять все / Отклонить / По одному» (N3).
- Plan mode: сначала план, запись запрещена до одобрения (N1).

## 8. Память

Память — то, что делает ассистента коллегой, а не одноразовым чатом.

### 8.1 Области

| Область | Что хранит | Кто видит |
|---|---|---|
| `user` (глобальная) | кто пользователь, стек, предпочтения, стиль общения, запреты, повторяющиеся решения | Всегда |
| `workspace` | факты и решения по конкретной папке: архитектура, договорённости, «сюда не лезем» | Когда папка активна |
| `session` | временные заметки текущей задачи (не переживают «очистить вид», но остаются в БД) | В текущем окне |

### 8.2 Типы записей

`fact`, `decision`, `rejected`, `preference`, `pattern`.

### 8.3 Запись

- Явно: `/remember <текст>` (в активную область; `/remember user <текст>` — в глобальную).
- Инструментом памяти.
- Автоизвлечение на границе задачи (дешёвая модель, опционально): «что решили», «что отвергли и почему», «какие ограничения».
- Автозапоминание **никогда** не перезаписывает существующее молча: только добавление с дедупликацией и понижением confidence у старого.

### 8.4 Чтение

- FTS5 + эмбеддинги, слияние RRF.
- При активной папке: top-k по области `workspace` + top-k по `user`.
- Запросы «что мы решали про X» — сначала по памяти, потом по истории сообщений.

### 8.5 Панель и обслуживание

- Через чат: `/memory`, `/memory search`, `/remember`, `/memory delete`, `/secret …`. Отдельной панели нет.
- Консолидация раз в сутки: дедупликация, слияние дублей, понижение устаревшего.
- Экспорт/импорт памяти в Markdown — чтобы не было lock-in.

## 10. Провайдеры LLM

### 10.1 Принцип

Никакого предзашитого каталога «ChatGPT / Gemini / …». Пользователь добавляет **любое количество OpenAI-совместимых провайдеров** через поля: название, Base URL, ключ.

- Название — произвольная строка (кириллица, эмодзи, дубликаты разрешены; при совпадении — мягкое предупреждение).
- Проверка `GET /models`; при ошибке — реальный статус и тело. Есть «Сохранить без проверки».
- Ключи — в локальную БД (`providers.api_key`); в экспорте маскируются.
- Роли моделей: `default`, `cheap` (компакция, заголовки, память), `embed`.
- Стриминг SSE, tool-calls, usage, отмена, ретраи, fallback при 5xx/429.
- Reasoning-поля сохраняются отдельно и не смешиваются с ответом.
- Локальные endpoint'ы (`127.0.0.1`: Ollama, vLLM, LM Studio, llama.cpp) — без прокси, офлайн.
- Стоимость: цена за 1M input/output в настройках провайдера → `/cost`.

### 10.2 UI

Реализовано: настройки → вкладка «Провайдеры» → список строк (статус-точка, название, хост, модель, контекст, бейдж `default`, меню `⋯`).
Пустое состояние — приглашение добавить провайдера.
Форма — один sheet: «Подключение» (название, Base URL, токен, проверка `/models`), «Модель» (выпадающий список или ручной ввод, окно контекста, уровень размышлений: выключено / минимальный / средний / максимальный), переключатель «по умолчанию».
Селектор модели в композере пока не реализован; в футере показывается имя активного провайдера, заданное пользователем.

## 11. MCP

- Транспорты: stdio, HTTP, SSE.
- Жизненный цикл: запуск, handshake, `tools/list`, вызовы, перезапуск, health.
- CRUD: add / list / enable / disable / edit / remove / test / login / logout / refresh.
- Scope: global (`config/mcp.json`) и «для папки» (файл `.mcp.json` в рабочей папке после доверия).
- Exposure: `direct` / `deferred` (по умолчанию) / `hidden`.
- Конфликт имён: префикс `<server>__<tool>`.
- Ошибка сервера — плашка в UI и результат агенту, без падения.
- Секреты — в локальной БД; в JSON только ссылки `${secret:alias}`.
- Hot-reload по FSEvents.

- Загрузка по требованию: в промпт — имя и описание, тело — при активации.
- CRUD: new / import / list / enable / disable / edit / remove / pin / update.
- Конфликт имён: пользовательский перекрывает встроенный.
- `allowed-tools` ограничивает набор инструментов на время работы.
- Предложения скиллов (`skill_proposals`) — только предложение, не автосоздание.
- Hot-reload по FSEvents.

## 13. Планировщик

- Типы: `run_at`, `cron`, `notify`.
- Таймзона IANA, хранение UTC, отображение локально.

## 14. Поиск и индексация

### 14.1 Что индексируется

- Рабочая папка (код, тексты, конфиги, PDF-текст, Markdown).
- История чата (сообщения, саммари).
- Память.

### 14.2 Правила

- **`.gitignore` — источник истины**: вложенные `.gitignore`, `.git/info/exclude`, `core.excludesFile`, плюс `.harnessignore` только на добавление.
- Список файлов: `git ls-files -z --cached --others --exclude-standard`; не-ignored untracked тоже индексируются.
- Дополнительно исключаются: `.git`, `node_modules`, `vendor`, `Pods`, `DerivedData`, `build`, `dist`, `*.min.js`, `*.map`, бинарники, файлы > 1 МБ (без чанков).
- Чанкинг: tree-sitter по классам/функциям; для прочего — по секциям 40–120 строк; перекрытие 5–10 строк.
- Инкремент: FSEvents → debounce 500 мс → mtime+size+hash → пересчёт только изменённого.
- Изменение `.gitignore` → перевалидация статусов; ignored-файлы вычищаются из всех слоёв.
- `code_search` никогда не возвращает ignored-файлы; `read_file`/`grep` могут, но с пометкой.

### 14.3 Поиск

- Гибрид: FTS5 + KNN (`sqlite-vec`, 768), слияние RRF.
- `search` — инструмент агента; глобальный поиск — ⌘⇧F и палитра.
- Запрос «о чём говорили в прошлый вторник»: фильтр по `ts`/типу → саммари → сообщения → RRF. Цель p95 < 100 мс.
- Переиндексация: кнопка + автораз в 5 минут; прогресс-события.

### 14.4 Бюджеты

| Метрика | Цель |
|---|---|
| Первичная индексация 50k файлов | < 10 мин в фоне |
| Инкремент одного файла | < 300 мс |
| Поиск p95 | < 150 мс |
| Размер индекса | ≤ 40% исходников |

## 17. UI: нативный macOS

> **Реализовано иначе по прямому запросу пользователя:** интерфейс намеренно сделан терминальным — моноширинный транскрипт, без пузырей и карточек. Пункты §17.1/§17.8 о строгом HIG-подражании считать смягчёнными; нативные контролы, системные шрифты, темы и доступность сохраняются.

**Главный принцип: это macOS-приложение, а не веб-страница в окне.** Никакого воспроизведения CSS, самодельных контролов, «карточек с тенями» и кастомных скроллбаров. Проверка на каждом экране: *«Если убрать логотип — это выглядит как приложение Apple?»*

### 17.1 Язык дизайна

- HIG — источник истины.
- Материалы: `NSVisualEffectView`, `.regularMaterial`, `.sidebar`.
- Иконки — SF Symbols (`Image(systemName:)`, `.symbolRenderingMode(.hierarchical)`).
- Шрифты — системные (`Font.system`, `NSFont.preferredFont`).
- Отступы — 8-pt сетка; окно чата без боковых панелей.
- Радиусы системные, тени только у окон/popover/menu.
- Анимации 150–250 мс, стандартные кривые.

### 17.2 Окно и хром

- Одно окно; `fullSizeContentView`, прозрачный titlebar, системный светофор.
- `.toolbar` (`unifiedCompact`): слева — рабочая папка, центр — провайдер/модель, справа — тема и настройки.
- Восстановление размера и позиции окна.
- Полноэкранный режим, Stage Manager — штатно.

### 17.3 Схема экрана

```
┌──────────────────────────────────────────────────────────────────────┐
│ Харнес   📁 project-x ▾   Модель: DeepSeek ▾   12k/128k   🔍  ⚙     │
├──────────────────────────────────────────────────────┬───────────────┤
│                                                      │
│   [виртуализованный транскрипт]                       │
│                                                      │
│   ▸ Расписание «Проверка сайта» · 13:00 · выполнено   │
│                                                      │
├──────────────────────────────────────────────────────┤
│ [вложения]                                           │
│ ┌──────────────────────────────────────────────────┐ │               │
│ │ Напиши…                                  [Стоп] ▶│
│ └──────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

Никакого списка чатов слева. Никаких «Проекты / Заметки» как вкладок приложения и никакой боковой панели.
Меню чипа `📁 project-x ▾`: список известных папок, «Открыть другую папку…», «Открыть только на чтение», «Показать в Finder», «Забыть папку».

### 17.4 Транскрипт

- Виртуализованный список (AppKit), окно ≤ 200 сообщений / ≤ 2 МБ.
- Ячейки: Markdown, код с подсветкой, диффы, tool-вызовы (сворачиваемые), вложения, карточки потоков.
- Стриминг обновляет только последнюю ячейку.
- Автоскролл с прилипанием к низу; кнопка «вниз» при прокрутке вверх.
- Сообщения — не «пузыри», а блоки: роль, время, контент; сообщения пользователя визуально отделены фоном и полосой. Блоки кода имеют кнопку копирования. Reasoning — свёрнутый жёлтый блок, раскрывается по клику.
- ⌘F — поиск по чату с подсветкой и переходом.

### 17.5 Композер

- Многострочный `NSTextView` с автовысотой; Return — отправить, ⇧Return — перенос (настройка).
- Вложения: drag-n-drop, ⌘V из буфера, кнопка.
- `/` — команды, `@` — файлы рабочей папки.
- Справа: `Стоп` во время стрима, `▶` в покое.
- Под полем: полоса контекста (`12k / 128k`) и выбор модели.
- Черновик сохраняется между переключениями и перезапуском.
- Очередь: во время ответа можно отправлять новые сообщения — они встают в очередь и обрабатываются по одному.

### 17.6 Контролы и состояния

- Кнопки: `.borderedProminent` — основное, `.bordered` — обычное, `.borderless` — в тулбаре.
- Пустые состояния — `ContentUnavailableView`.
- Загрузка — `ProgressView`.
- Ошибки — `Alert` для блокирующих, inline для полей, `ContentUnavailableView` для сбоя загрузки.
- Контекстные меню — на всех списках.
- Drag & drop — системный, с подсветкой цели.

### 17.7 Доступность

- VoiceOver: `accessibilityLabel`/`Value` везде, где нет текста.
- `accessibilityReduceMotion`, `ReduceTransparency`, `DifferentiateWithoutColor`.
- Контраст ≥ 4.5:1; смысл не только цветом.
- Полная работа с клавиатуры; системный focus ring.

### 17.8 Чего не делаем

- Своих кнопок, чекбоксов, скроллбаров, теней, градиентов.
- «Карточек» как основного контейнера — `List`, `Form`, `GroupBox`, секции.
- Модалок поверх модалок.
- Фирменных шрифтов и кислотных акцентов.
- Игнорирования системных настроек темы/контраста/размера текста.

## 19. Конкурентность

- `@MainActor` — только UI.
- Сервисы — `actor`.
- БД: один `DatabaseWriter`, чтения — `DatabaseReader` пул.
- Долгие операции — `Task.detached`/`TaskGroup`; результат возвращается в actor.
- UI получает только `Sendable` DTO.
- `RunHandle` с отменой; закрытие окна не отменяет запуск; выход из приложения — отменяет и сохраняет состояние.
- Один активный запуск в чате; расписания и субагенты — параллельно в своих потоках.
- Индексатор: один проход на папку, 2–4 воркера, `AsyncSemaphore`.

EventBus — `AsyncStream<AppEvent>`: дельты, tool-события, компакция, потоки, прогресс индекса, MCP health, расписания, обновления.

## 20. Ошибки, логи, восстановление

- `AppError` с категориями; в UI — человеческий текст + детали; агенту — код и подсказка.
- `os.Logger` (subsystem `app.project-s.swift`), файловые логи с ротацией (14 дней).
- Никогда не логировать ключи и содержимое сообщений.
- Диагностика: версия, железо, размер БД/индексов, пинг провайдера, MCP health, `quick_check`, экспорт zip без секретов.
- Восстановление: битая БД → бэкап; `SQLITE_BUSY` → таймаут+ретрай; падение стрима → `interrupted` + «Продолжить»; падение индексации → продолжение с очереди; битый артефакт → пометка; нет места → явная ошибка.

## 27. Риски и открытые вопросы

1. **Эмбеддинги.** ONNX Runtime Swift даёт совместимость 1:1 с EmbeddingGemma 2 (768); Core ML/MLX — быстрее, но требует переиндексации и проверки качества. Решить на P7 по замерам.
2. **Markdown-рендер без WebView.** `swift-markdown` + TextKit 2 — объём работы; WebView запрещён. Ограничить поддерживаемые конструкции (заголовки, списки, код, таблицы, ссылки, цитаты).
3. **Подсветка кода.** Нужен лексер; ограничить топ-языками (Swift, PHP, JS/TS, Python, JSON, YAML, SQL, Bash, HTML/CSS).
4. **CDP.** Нужен установленный Chrome/Chromium; понятная ошибка и выбор профиля.
5. **SSH.** Системный `ssh` через `Process`, не библиотека.
6. **`sqlite-vec`.** C-модуль + биндинги; проверить с GRDB и кастомной сборкой SQLite.
7. **Half-implemented chat tools.** `new_chat`/`delete_chat` сохраняются по имени ради скиллов, но маппятся на «очистить вид»/no-op; описать в промпте.
8. **Объём.** ~40–60k строк Swift. P0–P4 — рабочий минимум; P5–P9 — доведение.
9. **macOS 27.** На момент написания актуальна macOS 26; сборка под 27 означает, что приложение не запустится на существующих системах до выхода следующей версии. Подтвердить перед P0.
