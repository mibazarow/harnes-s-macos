#### S1. Фоновый запуск: родитель не блокируется

**Симптом.** Сейчас `task` — блокирующий `await` (`ToolRegistry+Agent.swift:82`).
Пока субагент работает, весь ход родителя стоит: нельзя ни ответить пользователю,
ни запустить второго.

**Что делать.** `task` возвращается сразу с идентификатором, а результат
приходит отдельным сообщением в транскрипт, когда ребёнок закончил.

- `runSubagent` создаёт `Task {}`, регистрирует его в новом
  `Core/Agent/SubagentRunner.swift` (актор, `[String: Task<Void, Never>]` по id),
  и **немедленно** возвращает `.ok("Подагент agent-2 запущен: <краткая задача>")`.
- По завершении `Task` дописывает в `ChatStore` сообщение роли `.assistant` с
  маркером `subagentReport(id:agent-2)`; рендерится как отдельный блок «отчёт
  подагента agent-2», не как обычный ответ.
- Родитель **не** получает результат в свой контекст автоматически. Отчёт
  приходит только в транскрипт, а модель читает его через `subagent_status`
  (S2). Иначе контекст распухает от десяти отчётов.
- Ограничение: фон разрешён только когда `!isSubagent` (глубина 1), чтобы не
  плодить деревья без контроля. Уже есть `SubagentRegistry.maxDepth`.
- `SubagentDelivery` больше не нужен как переключатель: `.parent` — это и есть
  фон, `.caller` — старый синхронный режим, оставить для тестов и для случаев,
  когда родителю нужен результат в том же шаге (`delivery: "caller"`).

**Как проверять.** Тест: два `task` в одном ответе модели → оба стартуют, второй
не ждёт первый; родитель отдаёт ответ пользователю, пока дети работают.
Ручной прогон: попросить «запусти подагента, который прочитает 20 файлов» и
сразу задать другой вопрос — ответ должен прийти.

**Не ломать.** `AgentAbortSignal` (`Core/Agent/GUIControl.swift:174`) должен
гасить и фоновые задачи: при `abort` пройти по `SubagentRunner` и отменить все.

#### S2. Инструмент `subagent_status` и отчёт по номеру

**Заказ.** «Я в любой момент могу тебя спросить, так, что там делает субагент
номер 2? … на какой он стадии».

**Что делать.** Новый инструмент `subagent_status`, exposure `.core`
(пользователь спрашивает часто, прятать за `tool_load` нельзя).

Аргументы:
- `id: String?` — конкретный подагент. Пусто = все.
- `interrupt: Bool = false` — остановить (только если `id` указан).

Вывод для одного:
```
agent-2 · работает 1:47 · шаг 4/12 · 11 вызовов
задача: прочитать TASKS.md и собрать список D-пунктов
последний инструмент: fs_read (2 с назад)
```
Для списка — по строке на каждого плюс итог.

**Данные для статуса.** `SubagentRegistry.Child` сейчас хранит только
`id/parent/depth/cancelled/reason`. Добавить (аддитивно, это актор в памяти, не
БД — миграция не нужна):
- `startedAt: Date`
- `title: String` — первые 60 символов задачи, одна строка
- `step: Int`, `maxSteps: Int`
- `lastTool: String?`, `lastToolAt: Date?`
- `finishedAt: Date?`, `outcome: String?` (для «уже закончил»)

Обновление из `ChatStore.subagent` — на каждой итерации цикла и на каждом
вызове инструмента. Это дешёвая запись в актор, не в БД.

**Как проверять.** Тест: запустить подагента, через `subagent_status` увидеть
растущий `step`; после завершения — `finishedAt` и итог. Прерывание через
`interrupt: true` останавливает и возвращает строку из `SubagentRegistry`.

#### S3. Промпт субагента — английский

**Заказ.** «Даёшь ему промт на английском языке, и субагент с тобой на английском
языке общается… так быстрее и эффективнее».

**Что делать.** Разделить языки явно, не полагаясь на модель.

- Системный промпт подагента — на английском, отдельная константа в
  `Core/Agent/Prompts.swift` (рядом с существующими). В нём: роль, запрет на
  preamble, требование отчёта в конце, правило «работай до конца, не спрашивай».
- `runSubagent` **не переводит** `prompt` — родитель сам пишет задачу
  по-английски. В `ToolDefinitions.swift:544` в описании `task` добавить прямо:
  `"prompt: write in English. The subagent answers in English."`
- Отчёт ребёнка возвращается как есть, по-английски. **Родитель переводит его
  пользователю** — в русском ответе, по-русски, без дословного пересказа.

**Важно.** Это не отменяет правила «тексты для модели английские, интерфейс
русский» (R30). Отчёт подагента в UI показывать по-английски (это его слова),
но заголовок блока и статусы — по-русски.

**Как проверять.** Ручной прогон: дать задачу, убедиться, что отчёт на
английском, а ответ пользователю — на русском.

#### S4. Пилюли субагентов в шапке

**Заказ.** «Сверху. У нас это как раз большое пустое место в окне. Там, где
настройки, глазик… такими пилюлями будут написаны короткая задача… пилюля — это
один субагент… какая-то крутилка, индикатор, что он там не повис».

**Где.** `App/RootView.swift:182`, `HeaderBar`. Пустое место — между `Spacer`
(строка 201) и пилюлей `plan` (строка 203).

**Что рисовать.** `HStack(spacing: 6)` с `ForEach` по `SubagentRegistry.snapshot()`.
Одна пилюля:

```
[◐ agent-2 · читает TASKS.md · 1:47]
```

- слева — индикатор: `ProgressView` в `.circular` масштабе 0.5, **крутится**,
  пока `finishedAt == nil`. Это и есть «не повис».
- `agent-N` — моноширинным, как остальная шапка (`AppFont.mono(11)`).
- `title` — обрезать до 40 символов, `lineLimit(1)`, `truncationMode(.tail)`.
- справа — прошедшее время, обновляется `TimelineView(.periodic(from:by: 1))`.
- фон — `palette.panel`, обводка `palette.border`, `clipShape(Capsule())`.
  Завершённый — `palette.dim` и без крутилки, иконка `checkmark`.
  Прерванный — `palette.error` (или ближайший аналог в `Palette`), иконка `xmark`.

**Клик по пилюле** — по заказу не стоп, а показать подробности. `popover` с
тем же текстом, что даёт `subagent_status`, плюс кнопка «Остановить»
(вызывает `interrupt`, это уже есть в реестре).

**Почему не стоп по клику.** Миха: «давай, даже стопа не нужно, просто какая-то
крутилка, индикатор, что он там не повис». Случайный клик не должен убивать
работу.

**Ширина.** Пилюль может быть много. Ограничить: показывать первые 3, дальше
`+4` в отдельной пилюле-счётчике, по клику — список. Иначе шапка расползётся.

**Как проверять.** Скриншот шапки с двумя работающими подагентами; проверить,
что время тикает, крутилка крутится, после завершения пилюля меняет вид.

#### S5. Отдельная модель для субагентов (оптом на всех)

**Заказ.** «В настройках нужно внести, что я могу указать отдельную модель для
субагентов… оптом на всех субагентов».

**Что есть.** `Provider.cheapModel` (`Models/StorageModels.swift:42`), выбор в
`UI/Settings/ProvidersSettingsView.swift:282`. Сейчас он используется так
(`Models/ChatStore.swift:666`):

```swift
let subagentModel = readOnly ? (provider.cheapModel ?? model) : model
```

То есть дешёвая модель берётся **только для read-only** подагентов, а
пишущий подагент идёт на основной. Это не то, что просит Миха.

**Что делать.** Новое поле `Provider.subagentModel: String?` рядом с
`cheapModel`.

- Миграция GRDB **аддитивная**: `v27_provider_subagent_model`,
  `ALTER TABLE providers ADD COLUMN subagent_model TEXT;` — по образцу
  `v19_memory_supersedes` (`Storage/AppDatabase.swift:440`). Существующие
  строки получают `NULL` = «как основная».
- `ProvidersService` — добавить колонку в оба `INSERT`/`UPDATE`
  (`Services/ProvidersService.swift:63` и `:77`).
- В `UI/Settings/ProvidersSettingsView.swift` — второй `Picker` под «Дешёвая
  модель»: «Модель для подагентов», первый пункт «Как основная» (пустая строка).
- `ChatStore.swift:666` заменить на:
  ```swift
  let subagentModel = provider.subagentModel.flatMap { $0.isEmpty ? nil : $0 }
      ?? (readOnly ? provider.cheapModel : nil)
      ?? model
  ```
  Порядок: явная настройка → дешёвая (для read-only) → основная.
- `cheapModel` **не удалять**: он ещё используется в `ChatStore.swift:852` для
  служебных задач (заголовки, саммари).

**Как проверять.** Тест на миграцию: старая база открывается, колонка
добавлена, `subagentModel == nil`. Тест на выбор модели: при заданном
`subagentModel` подагент идёт на неё независимо от `read_only`.

#### S6. Надёжность: что должно быть верно после всех правок

Миха: «всё это нужно надёжно, отлично сделать, чтобы прям замечательно работало».

- **Ни один подагент не теряется.** `SubagentRunner` при старте приложения
  проверяет свою таблицу: задачи, чей `Task` не существует (упало приложение),
  помечаются прерванными с причиной `app_restart`, а не висят вечно крутилкой.
- **Ни один не висит.** Таймаут на подагента: `maxSteps` (12) плюс жёсткий
  потолок времени (10 минут). По истечении — `interrupt` с причиной
  `timeout`, отчёт «не успел за 10 минут, успел сделать: …».
- **Отмена каскадом.** `AgentAbortSignal.abort` → отменить все фоновые `Task` в
  `SubagentRunner`, дождаться, записать в журнал.
- **Параллельная запись в `ChatStore`.** Отчёты фоновых подагентов приходят
  асинхронно и могут совпасть с ходом родителя. `ChatStore` — `@Observable` на
  главном акторе; все записи из `SubagentRunner` делать через `await
  MainActor.run`, не из фона.
- **Тесты.** `Tests/SubagentRegistryTests.swift` уже есть — дополнить на
  параллельный запуск, на таймаут, на отмену всех, на выбор модели из S5.
  Целевой прогон: 0 failed, skipped не растёт.
- **Живая приёмка.** Проверяет Миха: запустить двух подагентов, увидеть пилюли,
  спросить «что там agent-1», получить отчёт, дождаться завершения и увидеть
  отчёт в транскрипте.

**Ограничения из шапки файла действуют:** миграции только добавляющие,
`project.yml` и `CODE_SIGN_IDENTITY` не трогать, сборка и тесты штатными
командами.


Ограничения, которые действуют на любую новую задачу:

- Миграции GRDB — **только добавляющие**. Формат данных на диске не ломать.
- Никаких правок в `bitrix/` и в вендорных зависимостях.
- `project.yml` и `CODE_SIGN_IDENTITY` не трогать.
- Сборка и тесты — штатными командами проекта, не самодельными скриптами.
- Если пункт упирается в отсутствующий инструмент (R18 `ui`, R19.1 `notify`) —
  писать в этот файл, не выдумывать обход.
