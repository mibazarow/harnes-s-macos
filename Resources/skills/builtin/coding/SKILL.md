# Разработка

## Порядок

1. Пойми задачу и активную папку.
2. Запусти `project_overview` — тип проекта, команды сборки, тестов и линта.
3. Найди нужные файлы: `fs_glob`, `fs_grep`, `fs_tree`, `search_code` (если папка проиндексирована).
3. Прочитай код до правки. Не выдумывай содержимое.
4. Составь короткий план в `todowrite`, если шагов больше двух.
5. Правь `apply_patch` (унифицированный дифф) или `edit_file`. Полная перезапись — только для новых файлов.
6. Для Битрикса: код в `local/`, ядро `bitrix/` не трогать, креды из `dbconn.php` не выводить.
7. PHP после правки проверяй `php -l <файл>`.
8. Собери и прогони тесты. Покажи реальный результат.
9. Отчитайся: что изменено, где, что проверено.

## Правила

- Не трогай файлы вне активной папки без подтверждения.
- Не удаляй пользовательские данные. Используй корзину и undo.
- Не коммить и не пушить без явной просьбы.
- Не отключай проверки, тесты или strict concurrency ради зелёного билда.
- Не оставляй недоделанные срезы.

## Диагностика

- Ошибка сборки: сначала полный текст ошибки, потом гипотеза, потом проверка.
- Не помогает — сужай бисекцией, а не перебором.
- После исправления проверь исходный сценарий, а не только сборку.
