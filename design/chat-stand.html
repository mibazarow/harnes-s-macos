Пустая цена — это null или 0? В formatList есть проверка на null, значит падает на чём-то другом. Надо посмотреть, что реально приходит из инфоблока. Скорее всего '' из базы, а не null — тогда number_format получает строку.

Смотрю, что реально приходит в массив:

bash php -r "var_dump((new PriceFormatter)->formatList([['name'=>'A','price'=>'']]))" готово
PHP Fatal error: Uncaught TypeError: number_format(): Argument #1 ($num) must be of type float, string given in PriceFormatter.php:24

Вот и всё. Баг в том, что '' не null — проверка не срабатывает, и строка уезжает в number_format. Правлю:

@@ -19,7 +19,11 @@ public function formatList(array $items): array
{
- $fmt = static fn (?float $price): string => $price === null
- ? 'по запросу'
- : number_format($price, $this->precision, ',', ' ');
+ $fmt = static fn (mixed $price): string => match (true) {
+ $price === null, $price === '' => 'по запросу',
+ !is_numeric($price) => 'по запросу',
+ default => number_format((float) $price, $this->precision, ',', ' '),
+ };

И тест, который этого не ловил — он передавал null, а не '':

// было
$items = [['name' => 'Тест', 'price' => null]];
// стало — добавил пустую строку и ноль
$items = [
    ['name' => 'Тест', 'price' => null],
    ['name' => 'Пусто', 'price' => ''],
    ['name' => 'Ноль', 'price' => 0],
];
$this->assertSame(['Тест — по запросу', 'Пусто — по запросу', 'Ноль — 0'], $formatter->formatList($items));

Тесты были зелёные, потому что единственный кейс в них подавал ровно то значение, которое код умеет обрабатывать. Классика: тест проверяет ветку, а не контракт.
