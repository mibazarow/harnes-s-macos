# design/ — макет интерфейса HARNES-S

Это **не приложение** и не код, который попадает в сборку. Это HTML-макет, чтобы
увидеть целевой внешний вид до правок Swift.

## Что открыть

- `mockup.html` — двойной клик, откроется в браузере. Работает офлайн, без зависимостей.
- `shots/` — статичные снимки для тех, кто не будет открывать HTML:
  `01-copper.png` — окно 1240, `02-copper-narrow.png` — окно 980,
  `03-palette-copper.png` — палитра ⌘K, `04-copper-reduce-transparency.png` —
  «Уменьшить прозрачность». Светлых и системных снимков нет: тема одна.

## Что внутри макета

| Элемент | Что показывает |
|---|---|
| Тулбар | стекло: `backdrop-filter: blur(30px) saturate(190%)`, верхний блик, волосяная граница |
| Контент | сплошной фон — стекла в слое контента нет (требование HIG, §8) |
| Транскрипт | без пузырей, роль капсом `labelTertiary`, контейнер 1100 px, текст 760 px |
| Блок кода | `radius.panel`, моно 12, кнопка «Копировать» по ховеру |
| Вызовы инструментов | вертикальный зазор **1 px** (решение: 1, не 4) |
| Композер | прямоугольник `radius 10`, не капсула; чипы модели/контекста/плана |
| Палитра команд (⌘K) | R34: поле поиска, список действий, ↑↓ и ↩ |
| Подсказки слэш-команд | то, что в коде называется `CommandPalette` — список над композером, правится по §10.5 |

## Переключатели внизу слева

- **прозрачность** — вкл/выкл. Выключено = имитация «Уменьшить прозрачность»:
  материалы обязаны стать сплошными. Проверка требования §8;
- **окно** — 1240 / 980 px, видно, как сжимается контейнер;
- **палитра ⌘K** — открывает R34. Не путать с `CommandPalette` в коде: там это
  подсказки слэш-команд над полем ввода.

## Чего в макете нет и не должно быть

- реального поведения агента, стриминга, вызовов инструментов;
- сайдбара с чатами (решено: один чат, без боковой панели);
- выбора темы — тема одна, Copper, всегда тёмная; светлой и системной палитры нет
  ни в макете, ни в приложении;
- `Nordwand Mono` в интерфейсе — по умолчанию SF Pro, моно только в коде.

## chat-stand.html — стенд одного диалога

Отдельный файл, не связан с `mockup.html`. Один и тот же диалог (вопрос, размышления,
два вызова инструмента — удачный и упавший, diff, код, таблица, статус) в восьми
оформлениях. Переключалка внизу окна или клавиши `1`–`8`; выбор запоминается в
`localStorage`, можно и ссылкой: `chat-stand.html?v=terminal`.

| Вариант | Что меняет |
|---|---|
| Как сейчас (Copper) | базовый: без пузырей, роль капсом, 760 px текст, 28 px между сообщениями |
| Плотный | 12,5 px / 1,42, зазор 16 px, компактные панели — больше влезает на экран |
| Контрастный | ярче текст и границы, роль и рельса пользователя в акценте |
| Пузыри | классические бабблы, юзер справа |
| Рельса | акцентная линия слева у каждого сообщения, без подложек |
| Терминал | моно везде, без панелей и рамок, `>` и `$` вместо ролей |
| Светлый | та же вёрстка на светлой палитре |
| Широкий код | текст 760 px, но код, тулзы, diff и таблицы на все 1100 px |

Крутить руками — переменные в `:root` (`--fs`, `--lh`, `--gap`, `--pad`, `--col`,
`--radius`) и блоки `body[data-v="..."]` в конце `<style>`.

Проверено: восемь вариантов, наложений блоков нет, горизонтального переполнения нет,
текст не обрезается, консоль чистая, клавиши и клики переключают.


## Как смотреть правильно

Открыть макет, открыть рядом настоящее приложение и Finder/System Settings. Смотреть
на плотность: 13 px основной текст, строки 28 px, контролы 24 px. Если макет кажется
«крупнее» системного — это ошибка макета, а не цель.
