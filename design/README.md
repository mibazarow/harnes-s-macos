# design/ — макет интерфейса HARNES-S

Это **не приложение** и не код, который попадает в сборку. Это HTML-макет, чтобы
увидеть целевой внешний вид до правок Swift.

## Что открыть

- `chat-stand.html` — двойной клик, откроется в браузере. Работает офлайн, без
  зависимостей. Статичный макет одного диалога: целевой вид, переключалки вариантов
  нет.
- `shots/` — снимки собранного приложения для тех, кто не будет открывать HTML:
  `window-1240.png` — окно 1240, `window-980.png` — окно 980,
  `palette.png` — палитра ⌘K.

## Тема

Тема одна — светлая «Пузыри». Тёмной палитры, системного режима и выбора темы нет
ни в макете, ни в приложении.

## Что внутри макета

| Элемент | Что показывает |
|---|---|
| Окно | `--outer` по краям, колонка чата 1100 px по центру |
| Транскрипт | оба сообщения в пузырях: пользователь справа, ответ слева; радиус 14, нижний угол 4 |
| Ширины | ответ — `100% − 50px`, пузырь пользователя — не больше 86% |
| Строка роли | её нет: имени роли и времени не показываем |
| Блок кода | `radius.panel`, моно 12 |
| Вызовы инструментов | вертикальный зазор **1 px** (решение: 1, не 4) |
| Композер | прямоугольник `radius 10`, не капсула; чипы модели/контекста/плана |
| Палитра команд (⌘K) | R34: поле поиска, список действий, ↑↓ и ↩ |
| Подсказки слэш-команд | то, что в коде называется `CommandPalette` — список над композером |

Разворачивание и сворачивание размышлений и вызовов инструментов по клику в макете
осталось: это поведение, а не вариант оформления.

## Чего в макете нет и не должно быть

- реального поведения агента, стриминга, вызовов инструментов;
- сайдбара с чатами (решено: один чат, без боковой панели);
- выбора темы — тема одна, светлая «Пузыри»;
- `Nordwand Mono` в интерфейсе — по умолчанию SF Pro, моно только в коде.

## Как смотреть правильно

Открыть макет, открыть рядом настоящее приложение и Finder/System Settings. Смотреть
на плотность: 13 px основной текст, строки 28 px, контролы 24 px. Если макет кажется
«крупнее» системного — это ошибка макета, а не цель.

## Пересборка снимков

Снимки в `shots/` снимаются из собранного приложения тестами
`Tests/DesignSnapshotTests.swift`: они рендерят те же вьюхи, что запускает
приложение, в PNG.

```bash
xcodebuild -project Harness.xcodeproj -scheme Harness -configuration Debug \
  -derivedDataPath .build -destination 'platform=macOS' test \
  -only-testing:HarnessTests/DesignSnapshotTests
```

Готовые файлы появляются в `$TMPDIR/harness-design/`; оттуда их и копируют в
`shots/`.
