# HARNES-S: что осталось

Обновлено 2026-11-14. Открытых задач по файлам, документам и инструментам нет: раздел 6
закрыт (см. коммиты про `fs_grep`, `fs_write`, `image_read` в истории git).

Как работать: один концерн — один коммит, короткое императивное сообщение, реальный
прогон тестов в ответе. Комментарии в коде — по-английски и про «почему». Если меняются
числа, зафиксированные в тексте, обновить `README.md` и
`ВОСПРОИЗВОДИМОЕ_ТЕХНИЧЕСКОЕ_ЗАДАНИЕ.md`. Не ломать `LoopGuard`, `runOutputBudget`,
обрезку выводов и `readOnly`.

## Отложено сознательно

- **Разрез `ChatStore`.** ~1 350 строк, 60+ членов. Поэтапно: механический перенос
  групп методов в extensions (`ChatStore+Turn/History/Compaction/Commands.swift`) со
  снятием `private` примерно с 15 членов, затем отдельный `CompactionCoordinator`.
  Делать отдельным ревью, без параллельных функциональных правок в том же файле.
- **Политика подтверждений `allow / ask / deny`.** `ask` требует диалога из середины
  цикла агента: continuation в execute, событие в `AgentLoop.Event`, шит в UI.
  Полумера «только deny в конфиге» не решает задачу.
- **Checkpoint хода.** `file_versions.turn_id`, `restoreTurn(id)`, команда `/undo-turn`.
  Пофайловые версии и trash уже дают обратимость.
- **`session_search`, hooks, песочница, параллельные подагенты.** Нет запроса;
  параллельным подагентам сначала нужен worktree на каждого писателя.
- **Профили инструментов и deferred для редких схем** — только если
  `testToolSchemaCostStaysInsideItsBudget` перевалит за потолок.
- **Скриншот `DOCS/screenshots/git.png`** показывает старый демо-диалог про два
  зеркала; перегенерировать через `Scripts/demo_screens.sh`.

## Баги из работы (новые, пополняется)

Формат записи: **что сломано** → как воспроизвести → чем починить. Пункт закрывается
удалением отсюда со ссылкой на коммит, как и раньше.

### B1. `stealthy_fetch` не обходит Avito

**Что сломано.** `mcp__scrapling__stealthy_fetch` на Avito отдаёт HTTP 439 с заглушкой
«Нужна небольшая проверка браузера». Stealth-режим существует ровно для таких сайтов и
не срабатывает.

**Воспроизвести.**

```
stealthy_fetch("https://www.avito.ru/rossiya/tovary_dlya_kompyutera?q=wifi+adapter+usb")
→ status 439, "Проверка пройдена, перенаправление..."
```

**Починить.** Проверить конфиг `scrapling-mcp`: включены ли `camoufox` и `solve_cloudflare`.
Добавить в вызов флаг `solve_cloudflare=true`. Если Avito использует свой челлендж (Qrator
или собственный), нужен реальный браузер с ожиданием редиректа: `wait_selector` на
элемент после проверки, `network_idle: true`, `retries: 3`.

### B2. `make_request` не принимает `proxy`

**Что сломано.** У `fetch`, `stealthy_fetch` и `session_fetch` параметр `proxy` есть, у
быстрого `make_request` — нет. При включённом VPN (FlClashX) российские сайты режут по IP:
DNS-shop отдаёт 401 на любой запрос, включая `curl` с браузерным User-Agent.

**Воспроизвести.**

```
make_request("https://www.dns-shop.ru/catalog/17a9eac716404e77/adaptery-wi-fi/")
→ status 401, пустое тело
curl -A "Mozilla/5.0 ... Chrome/131" <тот же URL>  → 401
```

**Починить.** Пробросить `proxy` в `make_request`. Плюс информативность: при 401/403 без
тела писать в ответ «вероятно, блокировка по IP или региону — попробуй другой proxy»,
а не возвращать пустую строку.

### B3. `browser` и `scrapling` не делят состояние

**Что сломано.** Это два независимых браузера. Куки, логины и пройденные челленджи не
переносятся: чтобы снять скриншот, приходится открывать сессию scrapling, а чтобы
получить текст — запускать заново `browser.goto`.

**Починить.** Либо `browser` принимает `session_id` от scrapling и работает через тот же
CDP-контекст, либо scrapling получает действие `cliсовместимое` с `browser.click` /
`browser.fill` — сейчас кликов по селектору в scrapling нет вообще, только `session_fetch`
и `screenshot`.

### B4. Нет кликов и ввода в scrapling

**Что сломано.** `scrapling` умеет только «загрузить и прочитать». Для форм, кнопок
«показать ещё» и авторизации приходится переключаться на `browser`, теряя сессию (см. B3).

**Починить.** Добавить `session_click(session_id, selector)` и
`session_fill(session_id, selector, value)` — Playwright под капотом уже есть, это
обёртки в несколько строк.

### B5. `screenshot` не умеет кроп и не возвращает путь

**Что сломано.** `mcp__scrapling__screenshot` возвращает картинку в чат, но не даёт
сохранить её в файл и не режет по области. `full_page` есть, `clip` — нет.

**Починить.** Параметры `clip: {x, y, width, height}` и `save_to: "/путь.png"`.

Ни одной схемы без реализации, ни одной заглушки, `TODO`/`FIXME` в `Core/Agent/`
отсутствуют. Группы: файлы 16, git 5, память 4, секреты 3, планировщик 3, агентское 3,
веб 5, документы 3, прочее 7.

**Что сделано хорошо (не трогать):** параллельные вызовы (`AgentLoop.swift:215`,
`parallelSafeTools`: fs_read/fs_list/fs_grep/fs_glob/fs_tree/read_many/search_code/
memory_search/websearch/webfetch бегут в `withTaskGroup`, мутирующий вызов разрывает

результата; `bash` при таймауте честно обрывается с сообщением.

### B6. `task` (подагент) возвращает пустой ответ

**Что сломано.** Вызов `task` с непустым промптом возвращает `(подагент ничего не вернул)`
вместо текста. Самая дорогая поломка: без подагента нет декомпозиции, всё приходится
делать в основном контексте.

**Воспроизвести.** `task(prompt: "перечисли файлы в /tmp")` — ответ пустой.
В `Tests/SubagentAndSearchTests.swift` есть 7 тестов, они проходят, значит расхождение
между тестовым путём и живым.

**Починить.** Проверить, что подагент получает `paths` и системный промпт; логировать
его завершение и причину пустого ответа (`finish_reason`, лимит шагов, обрыв стрима).
Пустой ответ должен быть ошибкой, а не валидным результатом.

### B7. `webfetch` отдаёт сырой HTML-мусор

**Что сломано.** На `https://allterra.ru/regions/` вернул тысячи строк: пустые строки,
пробельные отступы, дубли меню по 3–4 раза, содержимое до `<body>` включительно.
Читать невозможно, контекст сжигается на навигацию.

**Воспроизвести.** `webfetch("https://allterra.ru/regions/")`.

**Починить.** Прогонять через `scrapling` (`make_request` с `extraction_type: "markdown"`
даёт чистый результат на том же адресе). Если scrapling недоступен — свой минимум:
вырезать `<nav>`/`<footer>`/`<script>`/`<style>`, схлопнуть пустые строки, отдавать
текст с `limit`/`offset`. `webfetch` — последний резерв, он не должен быть главным
способом чтения сайта.

### B8. `screenshot` не умеет кроп и не возвращает путь

**Что сломано.** Инструмент снимает экран целиком и отдаёт картинку без пути к файлу —
нельзя ни переиспользовать, ни обрезать, ни отдать дальше в `ocr` по имени.

**Починить.** Параметры `clip: {x, y, width, height}` и `save_to: "/путь.png"`, плюс
возвращать путь в тексте ответа.

### B9. Планировщик не умеет одноразовые задачи

**Что сломано.** `schedule_add` принимает только `interval_minutes`. «Напомни завтра
в 15:00» или «через 2 часа» выразить нечем — только периодика.

**Починить.** Поле `at: ISO8601` (одноразовый запуск) как альтернатива интервалу.
После срабатывания задача удаляется сама. Хранить в той же таблице с колонкой `fires_at`.

### B10. `secret_get` не пишет аудит

**Что сломано.** `reveal: true` отдаёт пароль, но нигде не остаётся следа: когда, какой
алиас, кто запросил. При работе с продовыми доступами это плохо.

**Починить.** Писать строку в лог аудита при каждом `reveal: true` (алиас, время,
идентификатор хода). Без значения секрета. `secret_get` без `reveal` логировать не нужно —
это шум.

### B11. У агента нет доступа к своим логам

**Что сломано.** `~/HARNES_S_DATA/logs` есть, но инструмента для чтения нет — при
самодиагностике приходится идти через `bash`, а это обход политики.

**Починить.** Либо разрешить `fs_read` в `dataSubdirectories` для `logs` (проверить
`writeGuard`), либо отдельный `app_logs` с фильтрами `level`, `since`, `limit`.

### B12. `todowrite` ничего не гарантирует

**Что сломано.** Инструмент записывает план, но не связан с циклом: план можно объявить
и не выполнить, никто не заметит.

**Починить.** Хук в `AgentLoop`: если в плане есть `active` шаг и прошло больше N вызовов
без смены статуса — вставить напоминание в контекст. Число N подобрать, начать с 12.

### B13. Аргументы инструмента обрезаются молча, инструмент этого не знает

**Что сломано.** Самое опасное из всех: рантайм вырезает длинный **аргумент** вызова
и подставляет плейсхолдер, а инструмент получает обрубок и пишет его на диск как
нормальный контент. `fs_write` при этом отрабатывает корректно — append действительно
дописал в конец, файл не портился. Порча приходит сверху.

**Воспроизвести (сессия 14.11.2026).**

```
fs_write(path: "TASK_AGENT_FIXES.md", append: true, content: "<~3300 символов>")
→ Дописано: TASK_AGENT_FIXES.md (+40 симв.)
→ [дописано: -1 +1]

На диске появилась строка: "[обрезано при сохранении: 3301 символов]"
```

Хвост ответа `[дописано: -1 +1]` — единственный признак: +40 символов вместо +3300.
Если не сравнить ожидаемый размер с фактическим, подмену не заметить.

**Как защититься от повторения — в самом инструменте.** Валидация входных данных
не должна пропускать плейсхолдеры. Проверка дешёвая и точная:

1. **Детектор плейсхолдера.** Если `content` содержит `[обрезано при сохранении`,
   `[обрезано`, `…[обрезано`, `[truncated` или совпадает по виду с
   `^\[обрезано[^\]]*\]$` — вернуть `.fail("контент обрезан сверху, запись отменена:
   <первые 80 символов>"), **не касаясь файла**.

2. **Сверка размера.** `append`: ожидаемое = `originalSize + payload.count` (+1 если
   добавлен перевод строки). Фактическое — `FileLines.fileSize(url)`. Это **уже есть**
   в коде, строки 110–114: `guard ... actual == expected else { return .fail(...) }`.
   То есть защита существовала, но не сработала. Значит не совпало: `payload.count`
   считался от уже обрезанного контента, и ожидание совпало с обрубком. **Починить:
   сверять не только размер файла, но и то, что `expected` ≥ какой-то разумный
   минимум относительно исходного размера вызова** — либо логировать расхождение
   между заявленным `content.count` и реально записанным.

3. **Эхо контента в ответе.** Возвращать не только размер, но и первые/последние 60
   символов записанного. Тогда обрубок виден сразу в выводе, а не через `git diff`.

4. **Минимальная длина подозрительного совпадения.** Если `content` короче 100
   символов, а вызывался для файла крупнее 1 КБ — предупреждение в ответе, без отказа.

**Правило для агента, чтобы не наступить снова.** Не писать длинные тексты одним
вызовом. Порциями по 1500–2000 символов, `append: true`, и после каждой проверять,
что реально на диске (`wc -c` / `tail`). Если файл важен — сначала `git status`,
чтобы было куда откатиться.

**Почему это приоритет.** Без git восстановления нет вообще: `file_versions` делает
снапшот перед записью, но снапшот — это **новое** состояние старых файлов, он не
спасает от записи мусора поверх. Единственная настоящая страховка — не писать обрубок.
