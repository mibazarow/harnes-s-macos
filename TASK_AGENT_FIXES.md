# HARNES-S: что осталось

Обновлено 2026-11-15. Раунд R7–R12 закрыт. Сделано: входной бюджет окна считается от
`окно − резерв под ответ` (15%, не меньше 16k, не больше половины), порог с запасом и
защитой от вырождения на малых окнах; первые 3 сообщения не сворачиваются; схемы
инструментов учитываются в бюджете; `/compact` сжимает всегда, когда есть что; оценка
калибруется по фактическому `prompt_tokens` (`TokenCalibration`, диапазон 0.75–1.6);
фоновое сжатие перерезолвит провайдера; при переполнении четыре шага ужимания
85→70→50→35%; anti-thrash со страйками в `app_state` и одной пробной попыткой; сбой
саммаризатора не ротирует историю; реактивное сжатие при измеренных >60% бюджета; у
саммаризатора резерв 32k на вывод. Тесты: 328, падений нет.

## R13 закрыт

**Сделано 2026-11-15.**

- **Оценщик.** Стоимость tool-трафика считается по сериализованному JSON
  (`ToolCost`: вызов + результат, оболочка и экранирование), а не по очищенному тексту.
  Тексты сообщений меряются как JSON (`TokenEstimator.jsonTokens`), каталог схем — через
  тот же `ToolCost`. Это должно убрать разрыв `estimated` против `measured`, который был
  18.6%. Проверка на живой сессии не проводилась — нужен прогон и `prompt_tokens` в
  `latency.log`; цель — расхождение не хуже 5%.
- **R13.1, прунинг.** `ToolOutputPruner`: заглушка `[pruned: name, ok, N из M символов]` +
  первая строка; ошибки не трогаются; только сообщения старше начала текущей задачи;
  результат, встречающийся в последних четырёх сообщениях, остаётся; пачка не меньше
  20 000 токенов; режим `Tuning.toolOutputPruning` (по умолчанию `.reactive` — вместе со
  сжатием или на границе задачи). В базе текст полный: замена только в исходящем запросе.
- **R13.2, граница задачи.** Задача закрывается финальным ответом без инструментов или
  командой `/checkpoint`. На границе выводы закрытой задачи прунятся, задача длиннее 40
  сообщений один раз сворачивается в чекпойнт (через обычные кулдаун и страйки). Внутри
  задачи история не переписывается.
- **B1, `NoAttemptGuard`.** Три условия: запрос — императив (`FalseSuccessGuard.
  looksLikeActionRequest`), ответ — короткий явный отказ с первых 160 символов, вызовов
  инструментов нет. Формулировки сужены до «я не могу это сделать / выполнить»; `notice`
  убран из ленты, событие пишется в `latency.log`; исправлена заглавная после точки с
  запятой в корректирующем сообщении.
- Тесты: 342, падений нет. Добавлены `CompoundGuardsTests` и `ToolPruningTests`
  (формат заглушки, ошибки, ссылки в хвосте, порог пачки, режимы, сохранность текста в
  базе, граница задачи).

**Не проверено:** критерий приёмки «prompt меньше на 30%» требует живой сессии одинаковой
длины с прунингом и без; тестами покрыта логика, не эффект.

## R6. Бюджет схем: решение отложено по замеру

51 инструмент = 5 187 токенов из 5 600 (`Tuning.schemaTokenBudget`). Запас делят и
MCP-инструменты: `schemasTokenCost` считает `mcp__*`, новый сервер двигает число без
единой строки в `ToolRegistry`. Порядок при переполнении: укоротить описания →
deferred-каталог для редких групп → профили по режимам (ломают кэш префикса) → либо
осознанно поднять потолок с записью замера.

## Отложено сознательно

- **Политика подтверждений `allow / ask / deny`.** `ask` требует диалога из середины
  цикла: continuation в execute, событие в `AgentLoop.Event`, шит в UI.
- **Checkpoint хода.** `file_versions.turn_id`, `restoreTurn(id)`, `/undo-turn`.
- **`session_search`, hooks, песочница, параллельные подагенты.** Параллельным подагентам
  сначала нужен worktree на каждого писателя.
