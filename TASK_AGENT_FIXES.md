## Открытые пункты

### R15.5 — замер прунинга вывода инструментов

**Почему не сделано.** Живой прогон за пользователем: нужны два одинаковых прогона по 20+ шагов (`bash`/`read_many`) с
`Tuning.toolOutputPruning = .off` и `.budget` и числа из `latency.log`. Агент эти числа сам
создать не может — только человек на живой задаче.

Что прислать из `~/HARNES_S_DATA/logs/latency.log` по каждой сессии:

- `prompt_breakdown` (`phase=pre_prune` и обычную) на одном и том же шаге;
- строку `cache_hit=… prompt_tokens=…`;
- строку `pruned tool_results=… saved_tokens=…`, если была.

Критерий: `total_est` после прунинга и `prompt_tokens` того же запроса расходятся меньше чем
на 10% (отдельно с картинками и без); `prompt_tokens` на сопоставимом шаге падает не меньше
чем на 30% при том же числе шагов.

### R23 — приёмка `shortcut` и `app_script` на живом

**Почему не сделано.** Код готов (`31cf9e8`); живой прогон за пользователем: три сценария
требуют Календаря, Safari и гранта Automation, которых в тестовом прогоне нет.

### R16.6 — постоянный браузер: живая приёмка

Залогиниться в Chromium руками → перезапустить Harness → `browser action=open` открывает

`/json/list` с одним таргетом `type=page`.

## Не будет сделано никогда

Не лень, а защита TCC/SIP/подписи. Агент может открыть панель и объяснить, что нажать, но
не выдать грант.

- **TCC кодом не пишется:** `TCC.db` под SIP, `tccutil` умеет только `reset`.
- **SIP** — только из Recovery; не просить и не автоматизировать.
- **Пароли, `AXSecureTextField`, экран блокировки, диалоги аутентификации, FileVault** —
  недоступны по дизайну.
- **Форматирование и стирание дисков** (`diskutil eraseVolume`, `rm -rf` по системным путям,
  `hdiutil force`) — отказ, без обсуждения в автопилоте.
- **Чужие машины, сессии и пользователи** — не «локальное управление».
- **Память чужих процессов** (`task_for_pid`) — не делаем.
- **Keychain без спроса** — секреты живут в локальной БД (`secret_*`).
- **Голос** (TTS, wake-word, диктовка, always-on микрофон) — снят решением пользователя,
  не возвращать даже частично.
- **Сторонние CLI** (`cliclick`, `yabai`, `blueutil`, `mas`, `brightness`) в рантайм — только
  системные API, `pmset` и `launchctl` там, где нужен код возврата.
- **Роутер Keenetic 192.168.1.1** — не трогать без отдельного разрешения.
- **Windows-порт** — удалён (`4aac748`), не возвращать.

## Забрать у Мехи
### R31 — доделать у Мехи

**R31.3 — извлечение фактов перед сжатием.**
У Мехи перед тем, как выбросить сообщения, прогоняется извлечение устойчивых фактов в память.
У нас выбрасывается как есть. Сделать: перед обрезкой один ограниченный проход извлечения
фактов по отбрасываемой части, best-effort — падение извлечения не должно блокировать сжатие.
Проверка: после сжатия длинного чата в памяти есть факты из выброшенных сообщений.

нигде не показывается. Сделать: писать в `latency.log` отношение `estimate / actual` на
последних 20 запросах. При отклонении больше 15 % — подкрутить коэффициенты по факту.
Проверка: в логе есть строка с расхождением, видно, что оно в пределах 15 %.

### R32 — инструменты (от Мехи, не сделано)

**R32.1 — подсказка при провале, привязанная к гранту.**
Сейчас отказ в правах приходит текстом, и что нажать — угадывает пользователь. У Мехи есть
словарь «сигнатура ошибки → что именно сделать» с точным путём в настройках, привязанным

Проверка: отказ Screen Recording даёт строку с путём до панели; отказ SIP не даёт подсказки.

**R32.2 — BM25-отбор инструментов вместо `deferred`.**
Пятнадцать инструментов стоят в `exposure: .deferred` — модель их не видит и не узнаёт, что
они есть. У Мехи двухступенчатый отбор: ядерные всегда, плюс подобранные по запросу, плюс
явно названные в тексте, плюс недавние; при провале деградация в ограниченный безопасный
набор, а не в полный каталог. Сделать: отбор по запросу хода поверх бюджета схем.
Проверка: запрос «поставь будильник» вытягивает инструмент будильника, не вылезая за бюджет.

**R32.3 — контекст вызова с отменой.**
Долгие (`process`, `bash`, `watch`, `browser`) не отменяются извне: пользователь смотрит,
как агент делает не то, и может только ждать. Сделать: токен отмены в контексте вызова,
прерывание из UI и из канала связи.
Проверка: запущенный `bash` отменяется, процесс получает TERM, цикл агента продолжается.

**R32.4 — границы прямо в схеме.**
Лимиты (размер вывода, максимум записей, таймаут) сейчас известны только коду. Вынести
их в описание схемы, чтобы модель не просила заведомо больше.
Проверка: схема `fs_read` называет максимум строк и поведение при превышении.

### R34 — контекст: остаток (от Мехи, не сделано)

**R34.1 — бюджет на каждый always-on блок.**
Двенадцать блоков, общего бюджета нет: профиль, objective, MCP и список людей могут раздуть
системную часть так, что под сообщения не останется места. Сделать: доля на блок, рез по
числу записей, честная строка «ещё N не показано».
Проверка: длинный профиль не съедает окно, сообщения видны.

**R34.2 — бюджет из окна модели, а не константой.**
Сейчас бюджет задаётся числом в настройках провайдера и не связан с реальным окном модели.
При смене модели (32k → 128k) бюджет перебивается руками: иначе половина окна не используется
либо лезем за предел и получаем 400 от провайдера. У Мехи окно обнаружено автоматически
(`ModelContextPreferences` хранит найденное вне базы, чтобы не тащить миграцию), бюджет
производный. Сделать: считать `usable = context_window − резерв на ответ`, бюджет выводить
из него, ручное значение — только переопределение.
Проверка: переключение модели меняет бюджет без правки кода; превышение окна не даёт 400.

**R34.3 — окно и бюджет в настройках, с источником числа.**
Пользователь не видит, сколько занято, когда сработает свёртка и откуда взялось окно.
Сделать: строка вида «Окно: 128 000 · бюджет 102 400 (провайдер)» или «(вручную)».
Источник в подписи обязателен — иначе непонятно, почему бюджет такой.
Проверка: на экране видно заполнение окна, порог сжатия и откуда взято окно.

## Проверка системы при первом запуске (для чужих машин)

Пункт появился из-за раздачи сборки на GitHub: у человека на чистом маке может не быть
ни `Xcode Command Line Tools`, ни `python3`, ни `ripgrep`. Само приложение от этого не
падает, но часть инструментов молча не работает, и человек не понимает почему.

**Главное правило: агент ничего не устанавливает.** Ни `xcode-select --install`, ни `brew
install`, ни скачивания. Только сообщает факт и даёт инструкцию. Если человек захочет —
он сам попросит, и тогда (и только по явной просьбе) агент помогает текстом.

**R35.1 — проверка окружения при старте.**

Один раз за запуск приложения проверять наличие:

| Что | Зачем | Обязательность |
|---|---|---|
| `git` (`/usr/bin/git` или `xcrun --find git`) | `git_status`, `git_diff`, `git_log`, `git_commit` | обязательный |
| `python3` | чтение `.xlsx` через openpyxl (есть фолбэк) | необязательный |
| `rg` (`/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`) | быстрый поиск по коду (есть фолбэк на `grep`) | необязательный |

Проверка не должна ничего запускать в системе и не должна занимать больше ~50 мс: простой
поиск файла по фиксированным путям, без `Process`/`which` через shell, если это возможно.

**R35.2 — как и где сообщить.**

Форма: короткий текстовый блок в самом начале первого ответа агента в новом чате, отдельной
строкой от содержательного ответа. Без модалок, без кнопок, без «давай я поставлю».

Готовые формулировки (использовать дословно, менять только при явной необходимости):

- нет git:
  > На этой машине не установлены Xcode Command Line Tools, поэтому git-инструменты
  > (status, diff, log, commit) недоступны. Если они нужны — открой Терминал и выполни
  > `xcode-select --install`, потом согласись с системным диалогом. Остальное работает и без них.
- нет python3 (только если в этом чате реально читается `.xlsx`):
  > Для чтения xlsx нужен python3 с openpyxl; без него таблицы читаются упрощённо.
  > Установка: `xcode-select --install` (или python3 с python.org).
- нет rg:
  > Не найден ripgrep — поиск по коду работает через grep, просто медленнее.
  > Установка: `brew install ripgrep`.

**R35.3 — не повторять.**

Факт «уже сообщил» хранить в настройках (по одному флагу на каждую зависимость). Показывать
повторно только если состояние изменилось (появилось → пропало) или если пользователь прямо
спросил. Ключ сбрасывается вместе с настройками приложения.

**R35.4 — ошибка инструмента вместо «command not found».**

Если инструмент всё-таки дёрнул отсутствующий бинарник (человек запустил `git_status`

с пометкой «необязательно».

**R35.5 — README для скачавших.**

В `README.md` раздел «Требования» с тем же списком: macOS 27+, Apple Silicon, рекомендуется
`xcode-select --install`, опционально `ripgrep` и `python3`. Формулировать как в R35.2, без
обещаний «всё поставится само».

вызов `git_status` отдаёт человеческий текст, а не `command not found`.

## За пределами, но известно

Без отдельного решения не берётся:

- **iOS-устройства** (`idevice*`, установка IPA) — libimobiledevice вне политики, отдельный
  проект.
- **Bluetooth-сопряжение и audio-роутинг** — нужен Bluetooth-грант и сценарий; чтение списка
  сопряжённых в `network` допустимо без записи.
- **Печать в PDF из любого приложения** — только экспорт из самого приложения через AX-меню,
  `NSPrintOperation` по чужому окну не сделать.
- **Focus/DND напрямую** — формат БД закрыт, маршрут только через шорткат.
- **Настройки под root** (энергосбережение, обновления ПО, `pmset repeat`) — только через
  сохранённый sudo и `confirm`.
- **Параллельные GUI-сессии и Fast User Switching** — своя аутентификация.

## Вне этого репозитория

## Обслуживание с датой

**Сертификат подписи истекает 19.10.2027.** После этого designated requirement перестанет
совпадать и все гранты TCC отвалятся. Решение за пользователем: переподписать новым Apple
Development (быстро, раз в год, с повторной выдачей грантов) или сделать самоподписанный
сертификат на 10 лет (`security add-trusted-cert`, нужен admin).

## Правила работы

1. Сборка и тесты из `AGENTS.md`: `xcodegen generate`, затем `xcodebuild … test`.
2. Один пункт = код + тест, который падал бы до правки, + коммит на русском в императиве
   (см. `AGENTS.md`). История до этого правила остаётся на английском и не переписывается.
3. Release, установка в `/Applications` и пуш — только по отдельной команде.
4. Живой грант (Accessibility, Screen Recording, EventKit, Automation) кодом не выдаётся:
   код и тесты пишутся, в отчёте — «живой прогон за пользователем».
5. `schemaTokenBudget` не поднимать: сначала резать описания, потом отложенные схемы, только
   потом потолок — с записью «было / стало».
6. `Core/Agent/Prompts.swift` и `ToolDefinitions.swift` трогать только по прямому пункту
   задания.
7. `~/HARNES_S_DATA/` — живые данные: читать можно, писать только кодом приложения.
   `latency.log` не удалять.
8. Чужие процессы (модели, серверы, MCP) поднимает пользователь.
9. Закрытый пункт удаляется из этого файла целиком.
10. Подпись: bundle ID `app.project-s.swift` и `CODE_SIGN_IDENTITY` в `project.yml` не менять,
    флаг `-` в командной строке `xcodebuild` не передавать — иначе TCC теряет все гранты.
11. Не выдумывать сигнатуры API: сверяться с SDK и исходниками, а не писать по памяти.

## Как отчитываться

1. какие пункты закрыты, с коммитом на каждый;
2. что измерено до и после, числами;
3. что осталось открытым и почему;
4. какие правки потребовали решения, которого в задании не было.
