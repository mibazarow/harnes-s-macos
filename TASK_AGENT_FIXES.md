## 1. Разрезать `ChatStore`

`Models/ChatStore.swift` — ~1 350 строк и 60+ членов: очередь, стример, сборка истории,
компакция, хранилище, автопилот, командный роутер в одном `@MainActor @Observable`.

Поэтапно, без изменения поведения:

1. **Механический шаг.** Вынести группы методов в extensions в отдельные файлы:
   `ChatStore+Turn.swift` (send/runTurn/settle/finish), `ChatStore+History.swift`
   (buildHistory/prepareWindow/loadHistory/loadOlder/persist), `ChatStore+Compaction.swift`
   (schedule/compactIfNeeded/compactNow/checkpoint), `ChatStore+Commands.swift`
   (runCommand/notice/planMode). Придётся снять `private` примерно с 15 членов —
   это единственное содержательное изменение, всё остальное перенос.
2. **`CompactionCoordinator`.** Отдельный `@MainActor` тип с явными входами/выходами:
   тогда `fits` и границы компакции тестируются без всего ChatStore.
3. **Опционально `TurnRunner`.** Превращение `AgentLoop.Event` в баблы и персист.

Приёмка: полный прогон зелёный, `git diff -M` показывает только перемещения.

## 2. Политика подтверждений `allow / ask / deny`

Сейчас есть два полюса: обычный режим (пишет сразу, обратимость — снапшоты) и
`autopilot` (пишет без вопросов). Между ними пусто.

- Хранить политику в `app_state` как JSON: `toolName → allow|ask|deny`, дефолт `allow`.
- `deny` блокирует в `ToolRegistry.execute` и убирает схему из `schemas()`.
- `ask` требует диалога **из середины цикла**: continuation в execute, событие в
  `AgentLoop.Event`, шит в UI, таймаут и поведение при отмене. В headless (subagent)
  `ask` превращается в `.fail("требует подтверждения")`.
- `autopilot` = «всё allow»; plan mode по-прежнему сильнее политики (только чтение).
- UI: раздел в настройках со списком инструментов и трёхпозиционным переключателем.

Полумера «только deny в конфиге» не нужна: она не решает исходную боль.

## 3. Checkpoint хода

Есть пофайловые версии и trash (`file_versions`, `trash`), но нет «откатить результат
этого хода»: правка двенадцати файлов откатывается по одному.

- Миграция: `file_versions.turn_id`.
- `FileSafetyService.snapshot` принимает `turnID`; `ChatStore` выдаёт его на ход.
- Метод `restoreTurn(id)` — восстановить все файлы хода одной операцией.
- Точка входа: команда `/undo-turn` и кнопка в контекстном меню трейса хода.
- Тест: ход меняет 3 файла → откат возвращает все 3 и не трогает чужие версии.

Git не нужен: данные уже есть, не хватает группировки и входа.

## 5. Отложено сознательно

Не делать, пока не появится конкретный запрос или замер:

- **`session_search`** — поиск по прошлым репликам. Дизайн «один чат» снижает
  приоритет; индекс можно построить поверх `messages`, когда понадобится.
- **Hooks** на жизненный цикл инструментов — есть skills и MCP, перехвата нет.
- **Песочница для `bash`** — противоречит выбранной модели «правит файлы на моей
  машине»; если делать, то отдельным решением с явным переключателем.
- **Параллельные подагенты** — сначала worktree на каждого писателя, иначе снапшоты
  и правки конфликтуют. Пока подагент один и последовательный, это не горит.
- **Профили инструментов** и deferred-схемы для редких групп — только если
  `testToolSchemaCostStaysInsideItsBudget` перевалит за потолок.
