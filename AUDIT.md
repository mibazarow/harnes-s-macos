# Аудит HARNES-S против OpenCode, Hermes Agent и Claude Code

Дата: 2026-11-06. Проверялись публичные репозитории и документация:
`sst/opencode`, `NousResearch/hermes-agent`, `anthropics/claude-code`.

Цель: понять, что мы взяли, где улучшили и что ещё отстаёт.

---

## 1. Краткий вердикт

HARNES-S — не «копия OpenCode» и не «копия Claude Code». Это **персональный нативный агент под одного пользователя**, с уклоном в память, секреты и локальные модели. По ядру агентского цикла мы догнали OpenCode/Claude Code. По экосистеме (плагины, LSP, мультиплатформенные шлюзы, облачные песочницы) — сознательно нет, и это не цель.

Что мы взяли и не хуже:

| Возможность | OpenCode | Claude Code | Hermes | HARNES-S |
|---|---|---|---|---|
| Стриминг ответа + reasoning | да | да | да | да |
| Tool-calling цикл | да | да | да | да, без лимита шагов |
| MCP-клиент | да | да | да | да, stdio, живые серверы |
| Скиллы | да | да | да, с self-improve | да, ручные |
| Память | сессии | CLAUDE.md | FTS5 + LLM-саммари + Honcho | SQLite + FTS5 + локальные эмбеддинги |
| Планировщик | нет | нет | да | да |
| Subagents | да | да | да | да, изолированные |
| Undo/trash | да | да | да | да, версии + корзина |
| Планы/todo | да | да | да | да, видимая панель |
| Permissions | да, гранулярно | да | да | да, plan mode + autopilot |
| Vision | да | да | да | да |
| Браузер | через MCP | через MCP | через плагины | scrapling MCP → Playwright → webfetch |

Где мы **лучше** для этого пользователя:

1. **Пароли в локальной БД, а не в Keychain.** Ни один из трёх так не делает.
2. **Локальный EmbeddingGemma 2 через ONNX.** Работает офлайн, без ключей и без оплаты. У OpenCode/Hermes — облачные эмбеддинги или чужие провайдеры.
3. **Гибридный поиск с RRF** и деградацией до FTS — прозрачно и предсказуемо.
4. **Один чат без сессий/сайдбаров.** У OpenCode и Hermes сессии — основа UI.
5. **Один файл данных `~/HARNES_S_DATA`.** Понятно, где что лежит, легко бэкапить.
6. **Приоритет веб-доступа зашит в промпт**: scrapling → Playwright → fallback. Агент не тратит шаги на «попробую браузер».
7. **Русский интерфейс и ответы** при английском системном промпте.
8. **Тема Copper** — одна, тёмная, без переключателей.

## 2. Что мы закрыли в этом аудите

Найдены реальные дыры и исправлены:

- **Обратимость.** Не было undo. Добавлены `trash_paths`, `undo_list`, `restore_trashed`, `file_versions`, `restore_version`. Каждая запись/правка файла делает снапшот.
- **Видимый план.** Не было `todowrite`. Добавлены `todowrite`, `todo_read` и панель плана над композером. Парсер терпим к `text/content/title` и к разным статусам.
- **Git.** Не было инструментов. Добавлены `git_status`, `git_diff`, `git_log`.
- **Plan mode.** Добавлен режим «только чтение» с фильтрацией мутирующих инструментов.
- **Subagents.** Добавлен `task` — изолированный агент со своим контекстом, возвращает только результат.
- **Дерево проекта.** Добавлен `fs_tree`.
- **Тема.** Убрана светлая, оставлена Copper, ширина сообщений 85% (100% при окне < 800), зазор 10 pt.

## 4. Честная оценка

- **Как персональный ассистент** — да, это уже супер-ассистент: помнит, ищет, считает, ходит в интернет, пишет код, хранит пароли, работает по расписанию.
- **Как кодовый агент** — уверенный средний уровень: чтение/правка/поиск/bash/git/тесты есть, LSP и плагинов нет.
- **Как «супер-агент» в смысле автономности** — лимит шагов снят, plan mode и subagents есть, но нет самопланирования между сессиями и самообучения, как у Hermes.
- **Как продукт** — один пользователь, один Mac, один чат. Это ровно то, что было заказано.

Итог: **лучшее из трёх мы взяли, ключевые вещи улучшили под себя, а хвосты (LSP, плагины, remote MCP) — не про этот продукт.** Дальше имеет смысл вкладываться не в паритет фич, а в надёжность: реальные сценарии, восстановление после сбоев, стоимость токенов.
